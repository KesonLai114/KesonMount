## 重复挂载与路径不一致问题修复

### 问题描述
- 软件默认将网络硬盘挂载到 `~/Volumes/<名称>`，而 macOS 系统/访达挂载到 `/Volumes/<名称>`
- 导致同一块共享在桌面上出现两份图标（共四个硬盘）
- 用户在外部软件中配置的路径会因挂载位置不同而失效

### 解决方案
1. **Models.swift**: 重写 `resolvedMountPoint` 默认逻辑，统一指向 `/Volumes/<共享名>`
   - 新增 `standardMountPoint` 静态方法用于路径提取与标准化
   - 新增 `directMountPoint` 作为直连挂载兜底路径

2. **MountScanner.swift**: 实现服务器身份归一化与重复卷识别
   - 新增 `serverKey` 将各类主机名/IP 统一归一化
   - 新增 `redundant` 和 `preferred` 智能识别并筛选重复挂载点
   - 重写 `match` 使用服务器身份键+共享名进行精准匹配

3. **MountService.swift**: 重构挂载流程
   - 优先使用 `viaSystemMount`（AppleScript `mount volume`）确保挂载到 `/Volumes`
   - 将 `viaDirectMount` 降级为兜底方案，并改用 `directMountPoint`

4. **DriveStore.swift**: 配置迁移与自动清理
   - 新增 `migrateLegacyMountPoints` 自动清空配置中残留的 `~/Volumes/` 路径
   - 新增 `reconcileMounts` 负责启动时/导入时自动卸载重复卷并重新按新逻辑挂载
   - 在初始化、导入及刷新流程中调用该函数

5. **main.swift**: 添加"清理重复挂载"菜单入口及 `cleanDuplicates()` 方法

6. **ui.html & README.md**: 更新挂载点输入框提示文案与文档说明

### 验证结果
- 编译成功，无编译错误（仅有少量 weak capture 警告）
- 应用正常启动，菜单栏显示 2 块已挂载磁盘
- 菜单结构中"清理重复挂载"项已正确添加
- 手动测试卸载重复挂载成功，仅剩 `/Volumes/极空间HD` 和 `/Volumes/极空间SD` 两份标准挂载

### 技术要点
- Bonjour/NetBIOS 主机名归一化：`Z4S-I0C9._smb._tcp.local`、`Z4S-I0C9.local`、`192.168.31.4` 视为同一台 NAS
- 系统标准挂载路径：`/Volumes/<共享名>`
- 自动迁移老版本网盘管家配置，避免升级后继续产生重复挂载

## 菜单栏弹窗界面美化

### 问题
- 用户反馈菜单栏左键弹出的面板界面简陋（原版是纯列表 + 灰色系统按钮）
- 用户一度以为"改完没构建"——实际是改了源码但没跑 `./build.sh` 重装到 `/Applications`

### 解决方案
重写 `Sources/StatusPopover.swift`，改成「卡片 + 状态胶囊」风格：
- **头部**：App 图标 + 标题 + 版本号（拿不到图标时回退 SF Symbol `externaldrive.fill`）
- **概览**：已挂载数量 + 4pt 细进度条（全部挂载绿色，否则橙色）
- **列表**：每块盘一张圆角卡片（`DriveCard`），左侧协议图标底块、
  名称 + 状态胶囊（`BadgeView`：绿=已挂载/橙=连接中/黄=已跳过/灰=未挂载）、
  副标题、容量条（≥90% 转红）、右侧自绘操作按钮
- **底部**：自绘 `AccentButton`——强调色实心（打开网盘管家）+ 描边次按钮，带悬停/按下态

### 关键技术决策
1. **布局全部用 frame 手算，不用 Auto Layout**
   - `NSStackView.Alignment` 没有 `.fill`（垂直方向只有 leading/centerX/trailing）
   - 面板宽度固定 360，交叉轴拉伸行为在不同 macOS 版本不一致
   - 手算 frame 结果 100% 可预测，避免约束冲突导致的重叠/跑偏
2. **列表容器改成 `FlippedContainer`（`isFlipped = true`）**
   - 原先用 `NSStackView` 装卡片，两张卡会叠在一起（StackView 需要 intrinsic size，
     而 `NSView` 子类没有，撑不出高度）
   - 改为纯容器 + frame 手工排布，坐标从顶部往下递增
3. **刷新时用内容指纹去重**：`listSignature` 变了才重建列表，
   否则每 2 秒定时刷新会把悬停高亮、滚动位置全弄丢，点着的按钮也会消失
4. **`NSPopover.contentSize` 同步**：新增 `StatusPopoverController.panelWidth` 常量，
   `StatusBarController` 建弹窗时改用它，保证两边宽度一致

### 新增的自绘控件
- `DriveCard` — 圆角卡片 + 悬停高亮（NSTrackingArea）
- `BadgeView` — 状态胶囊（小圆点 + 文字，淡色底）
- `CapacityBar` — 细进度条
- `AccentButton` — 自绘胶囊按钮（`.accent` 实心 / `.neutral` 描边）
- `SeparatorLine` — 精确 1pt 分隔线（NSBox 高度受样式影响，不够精确）

### 验证方式
项目自带自检入口，不用手动点：
```bash
NETMOUNT_DUMP_STATUSBAR=1 NETMOUNT_DUMP_POPOVER=1 \
  NETMOUNT_SNAPSHOT_POPOVER=/tmp/popover.png \
  "/Applications/网盘管家.app/Contents/MacOS/NetMount"
```
会打印面板尺寸并渲染 PNG——改完 UI 直接看图，比反复手动点菜单栏快得多。

### 踩坑
- 网络盘（SMB）上直接 Write 文件常被 "File has been modified since read" 拦下
  （mtime 一直在变）。解法：先写到 `/tmp`，再 `cp` 覆盖过去
- `NSImage(systemSymbolName:)` 返回可选，`NSImageView(image:)` 不能直接接
- `NSView` 子类的 `init(frame:)` 里设 `translatesAutoresizingMaskIntoConstraints = false`
  会让 frame 布局失效（Auto Layout 接管后又没约束），纯 frame 布局时不要设

### 验证结果
- 编译通过（仅原有 weak capture / popUpMenu 弃用警告）
- `./build.sh` 已重装到 `/Applications/网盘管家.app`，进程运行中
- 渲染 PNG 确认：360×330，2 块盘，卡片不重叠、徽章和容量条位置正确

## 软件缺陷审查（全量审计）

用户要求"重点审查下软件，看看是否有遗漏的 BUG 或功能缺陷"。通读全部 18 个 Swift 源文件 + build.sh + Resources 后产出 `docs/软件审查报告.md`。核心结论：

### 高优先级（建议立即修）
1. **WebDAV 协议基本不可用**：
   - `MountService.swift:406` `connectionURL` 对 webdav 拼 `https://`（`mount volume` 只认 `webdav(s)://`）
   - `MountService.swift:261` `viaOpenURL` 同样用 `https`，`open https://` 是开浏览器不是挂载
   - `MountService.swift:241-245` `viaDirectMount` 的 webdav 分支漏了 `user:pass@host:port` → 带密码/自定义端口的 WebDAV 直连必败
   - 后果：系统路径失败→退回 ~/Volumes，把已修好的"路径统一"又带回来

### 中优先级
2. `MountScanner.swift:116-119` `match` 第 3 步按共享名盲匹配，会认错"不同服务器的同名共享"，误卸载别人的盘
3. `DriveStore.swift:24` `appMounted` 不持久化 → 重启后"挂载来源"永远显示"系统/访达挂载"
4. `DriveStore.swift:296` + `AppController.swift:560-573`：空密码被忽略，界面无法清除已存密码（只能删盘重建）
5. `MountService.swift:226` `mount_smbfs` 的 `soft` 选项可能不被支持（项目自己在 Models 注释里提过 `vers=2.1` 报 not supported），需实测

### 低优先级
6. `DriveStore.swift:409` `rememberIP` 守卫 `contains(".")` 跳过 NetBIOS 名 → 不缓存 IP，每次重解析
7. `MountWatchdog.swift:14-25` 超时后 `contentsOfDirectory` 僵尸读取堆积
8. `AppController.swift:325-356` `enrichDiscovered` 下标竞态
9. `MountScanner.swift:198` 导入即 `autoMount=true` 可能出乎意料
10. `DriveStore.swift:311` `upsert` 主线程扫挂载表（与自身 refresh() 约定冲突，轻微卡顿）

### 确认无误（增强信心）
- 状态集合严格主线程改 + watchdog 推副本，并发设计正确
- 服务器身份归一化（serverKey/hostAliases）周全，解决"同盘双图标"
- 密码走进程内 Security API，不落命令行参数
- 面板 frame 手算布局，`preferredHeight=190+listHeight` 与各区块累加精确吻合（已复核）
