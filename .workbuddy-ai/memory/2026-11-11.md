## 第三轮软件评估（基线 1.4.5，只评估未改代码）
- 结论已追加到 `docs/软件审查报告.md` 第六节：10 项 P0（稳定性/安全）、9 项 P1（功能缺口与文档脱节）、7 项 P2（工程化），另列「复核确认无误，不要重复修」清单。
- 最关键的新发现：
  - `Shell.swift:74-80` 超时分支 kill 后不 `waitUntilExit()`、不关读线程 → 假死盘每次卸载超时泄漏僵尸进程 + 2 个挂起线程 + fd。
  - `DriveStore.reconcileMounts()` 不占 busy、启动只靠固定 8s 延时避开 autoMount → 可能重复挂载或卸掉刚挂上的盘。
  - `Keychain.delete(for:)` 在 vault 未加载（冷启动直接删盘）时不删统一库里的密码 → 明文凭据永久残留，与 README「删除磁盘时一并清除」不符。
  - `DriveStore.load()` 跳过 `isSafeMountPoint`；导入按 id 覆盖且密码按 id 索引，伪造备份可把旧密码导向恶意主机。
  - `Models.userName` 取 `@` 前整串，遇 `//user:pass@host` 会把 `user:pass` 写进 snapshot / drives.json / 导出备份。
  - WebDAV 硬编码 `https://`，但说明书推荐 Alist 5244 纯 HTTP 端口 → 按说明书填必连不上；「挂载点」输入框仍可编辑但 1.4.5 已禁止自定义落点。
  - README「挂载是怎么做的」仍写直连三段式、说明书.html 残留 1.4.4 文案；README/项目记忆/当前代码对「整台服务器根」是否支持说法互相矛盾，需核对后统一。
  - 看门狗状态字典不随删盘清理、换网漏清 `notifiedDown`、WOL 唤醒通知无幂等；容量 statfs 无 inFlight 去重；发现流程回调无代次校验。
  - 工程层面：项目不是 git 仓库、无测试/CI、无 os_log 与诊断导出；固定 DR `identifier "com.keson.netmount"` 是 ad-hoc 签名的自觉取舍，别简单拆 vault（会退回每盘弹授权）。
- 复核确认无误（避免以后误改）：ui.html 的 `esc()` 全量转义、AppleScript 字符串转义、密码不进 argv、persist/export 原子写、看门狗退避与定时器配对、深色模式适配、`appMounted` 不持久化是设计取舍。
- 建议路线：1.4.6 修 P0 + 文档/表单一致性；1.5.0 做 git、单测、日志导出、状态源统一。本轮未修改任何源码。

## 1.6.0 全量优化（已构建 + 安装 + 提交，tag `v1.6.0` → `d65e576`）
- 用户先问「还能怎么优化」，给了四类建议；随后说「全部优化下」。落地前先核对：1.5.0 已吃掉上一轮建议里的 git / 测试 / Diagnostics / MountOps / WebDAV scheme / clearPassword / Wi-Fi 接口缓存，**不要重复做**。本轮只补真正剩下的 7 项。
- **性能**：`MountScanner.scan()` 改读 `getmntinfo(3)`（`MNT_NOWAIT`），不再每 4 秒 fork `/sbin/mount`；`/sbin/mount` + `parse()` 保留为兜底。附带修掉「共享名含 ` on ` 时 `range(of: " on ", options: .backwards)` 切错」的隐患。实测 getmntinfo 与 `/sbin/mount` 在真机上给出完全一致的 2 个 SMB 卷。
- **刷新节奏**：`AppController.tick()` 按 `webView.window.isVisible && !isMiniaturized` 决定 4 秒还是 30 秒；重新显示时立刻补刷；`StatusBarController.togglePopover` 打开面板前先 `store.refresh()`，避免窗口藏起来后看到 30 秒前的旧数据。
- **钥匙串**：`DriveStore.hasPassword` 改「只读缓存 + 后台预热」（`warmPasswordState` / `passwordPending` / `invalidatePasswordCache`）。主线程不再碰 `SecItemCopyMatching`，锁屏或授权框弹出不会冻界面。
- **修复 MountHealth**：`inFlight` 从 `Set` 改成 `[String: (token, started)]`，超过 `max(15, 3×timeout)` 视为那次探测已废、允许重派；完成时只删自己 token 那条；新增 `forget(path)`，`MountService.unmounted()` 成功卸载后调用。原缺陷：一次永久卡住的读会让该路径永远判死 → 重挂到同一 `/Volumes/<名>` 后每 5 分钟无谓重挂。
- **NFS 真挂载**：`viaPrivilegedNFSMount` 用 `do shell script "... mkdir -p … && /sbin/mount -t nfs …" with administrator privileges`（脚本走 stdin，不进 argv）。卸载加 `privileged:` 参数，只有 `DriveStore.unmount`（用户主动点）传 true，看门狗自动重连绝不弹框。终端命令仍由 `nfsMountCommand()` 给出（已抽出，便于测试转义）。
- **新功能**：`Sources/DeepLink.swift` 解析 `netmount://`（show/refresh/mountAll/unmountAll/mount|unmount|reconnect?id=），纯函数；`main.swift` 用 `NSAppleEventManager` + Carbon 的 `kInternetEventClass/kAEGetURL` 接事件；Info.plist 加 `CFBundleURLTypes`。`NotificationRouter`（UNUserNotificationCenterDelegate + UNNotificationCategory `netmount.driveDown`）给掉线通知加「立即重连」按钮，在 `DriveStore.init` 里 install。
- **测试**：95 项断言（原 75）。新增第 8 组深链接解析（含 `http://` / 未知动作 / 缺 id / 非 UUID 一律 nil）、NFS 命令单引号转义；第 9 组校验 `getmntinfo` 与 `/sbin/mount` 解析结果一致（带 3 次重试防抖动）。
- **验证**：`./scripts/check.sh` 全绿；`./build.sh` 安装到 /Applications；隐身截图确认界面与「1.6.0（构建 13）」正常；带 `NETMOUNT_LOG=1` 直接跑二进制，`open netmount://refresh` 打到「深链接：执行 refresh」、`netmount://nonsense` 打到「认不出…已忽略」，证明 URL scheme 端到端可用。
- 顺手：`Diagnostics.log` 在 `NETMOUNT_LOG=1` 时同时写 stderr（以前只有 os_log，沙箱里 `log show` 被拒，没法在终端排查）。
- 说明书同步到 1.6.0 并重新生成 25 页 PDF（`docs/网盘管家使用说明书-1.6.0.pdf`，排版检查全部在安全线内）；NFS 相关两处文案改为「弹系统授权框自动挂载」。README 加「从脚本 / 快捷指令调用」章节、功能表两行、1.6.0 版本记录。
- 未做：`./package.sh` 出 DMG/PKG（用户没要发布包）；`popUpMenu` deprecation 仍未动（改法会改变右键菜单弹出方式，风险大于收益）。
